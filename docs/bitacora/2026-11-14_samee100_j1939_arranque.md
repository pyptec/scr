## D. Máquina de estados y reglas

Se exige cantidad Y tiempo de confirmación; opción conservadora dentro del requerimiento. Se mide tiempo tanto monotónico de recepción como intervalo entre adquisiciones. | Estado/condición | Resultado |
|---|---|
| UNKNOWN + muestras bajas confirmadas | STOPPED sin STOP inventado |
| UNKNOWN + muestras altas confirmadas | RUNNING sin START inventado (motor encontrado funcionando) |
| STOPPED + RPM >= rpm_start | STARTING; confirmación → RUNNING y un START |
| RUNNING + RPM <= rpm_stop | STOPPING; confirmación → STOPPED y un STOP |
| Candidato + banda intermedia/retorno al estado estable | Cancelar candidato y recuperar baseline; sin evento físico |
| Muestra inválida del equipo/ECU objetivo | Romper candidatura; no contar como cero ni renovar timeout |
| Muestra ajena al equipo/SA/PGN/SPN | Ignorar para evidencia; no refresca comunicación |
| Repetida/fuera de orden | Ignorar para confirmación y frescura; no altera candidatura vigente |
| Hueco entre muestras > max_sample_gap_seconds | Reiniciar candidatura; no atravesar intervalos sin cobertura |
| Timeout sin RPM válidas objetivo | COMM_LOST una vez, preservar last_confirmed_state, jamás STOP |
| COMM_LOST + primera muestra válida/fresca objetivo | COMMUNICATION_RECOVERED una vez hacia UNKNOWN; iniciar reconfirmación |
| Reconstrucción tras pérdida | Confirmar estado nuevo sin START/STOP retrospectivos; después habilitar nuevos ciclos observados |

Timeout se evalúa antes de procesar cada muestra y también en poll. Si el llamador dejó pasar el plazo y vuelve con muestra válida, feed devuelve LOST seguido de RECOVERED: los dos hechos se reportan en orden al observar el retraso. Timestamp de evento corresponde al momento de detección, no a una hora física inferida. En arranque/parada previous_state es STARTING/STOPPING, respectivamente; baseline histórico se conserva en last_confirmed_state.

Antigüedad y fechas: muestra debe tener zona, timestamp creciente, no estar en el futuro y tener edad <= max_sample_age_seconds. ## H. Reinicios y recuperación

DirectoryLease usa lock de SO Windows/Linux liberado tras muerte del proceso, sin borrar locks por heurísticas de PID. Impide dos escritores en la misma carpeta. Recupera OPEN/.partial y rename sin manifiesto final, recalculando filas válidas/rango/hash; siempre INCOMPLETE tras cierre incierto. RAW huérfano queda sin sesión inventada. RAW faltante se marca MISSING. Manifiestos corruptos se preservan y se reportan; no sobrescribirlos para ocultar el daño.

Nuevos segmentos tras reinicio pueden asociarse a la misma sesión persistida al reconfirmar RUNNING. No hay STOP inventado ni sesión física completa por la sola presencia de un archivo COMPLETE. COMPLETE describe integridad del segmento dentro del alcance observado/configurado.

Recuperación limitada a max_files×4 manifiestos y max_files huérfanos; listas PGN/SA acotadas. Superar capacidad exige archivado/revisión explícita, no borrado.
