# J1939 pasivo en SAMEE100

El servicio J1939 es independiente de Modbus, SQLite, MQTT y Flask. Su API
interna escucha exclusivamente en `127.0.0.1`; Flask publica el proxy bajo
`/api/j1939`. No existe código para transmitir CAN.

## A. Hardware definitivo SAMEE100: SocketCAN

El PCB SAMEE100 usa el MCP2515 ya configurado por Linux y `can0` a 250 kbit/s.
SocketCAN es el transporte recomendado:

```text
J1939_ENABLED=true
J1939_TRANSPORT=socketcan
J1939_CAN_INTERFACE=can0
J1939_CAN_BITRATE=250000
```

El bitrate es solo metadato de diagnóstico. El servicio no ejecuta `ip link`,
no configura SPI ni Device Tree y no transmite CAN. Solo abre `can0` y llama
`recv()`.

## B. Herramientas de laboratorio: serial

El único formato confirmado por la referencia es una línea ASCII extendida:

```text
T<CAN_ID de 8 hex><DLC de 1 hex><payload sin separadores>\r
```

El transporte abre el puerto en modo lectura y no envía comandos. El baudrate
UART debe confirmarse con el convertidor real y se configura mediante
`J1939_SERIAL_BAUDRATE`. No se asume ningún comando LAWICEL de inicialización.

## C. Pruebas: replay

Copie las variables necesarias desde `config/j1939.env.example`, configure el
puerto y habilite explícitamente:

```text
J1939_ENABLED=true
```

Ejecución normal:

```text
python services/j1939_can_service.py
```

Replay offline, usando exactamente el mismo parser y decoder:

```text
python tools/j1939_serial_monitor.py --replay data/j1939_captures/CAPTURA.txt
```

## Capturas

Los archivos se guardan en `data/j1939_captures/` con formato UTF-8. La
adquisición inserta en una cola acotada y un hilo separado escribe al disco. Si
la cola se llena, la recepción continúa y aumenta `droppedCaptureFrames`.

No se borran capturas automáticamente. Al llegar a `J1939_CAPTURE_MAX_FILES`,
una captura nueva se rechaza con `CAPTURE_STORAGE_LIMIT`.

Los POST de captura no tienen autenticación propia porque SAMEE100 tampoco la
tiene actualmente. Deben exponerse únicamente en una red local confiable.

## Instalación y prueba pasiva en Raspberry

```bash
cd /home/pi/SAMEE100/scr
source /home/pi/medidorsamee100/bin/activate
python -m pip install -r requirements.txt
ip -details link show can0
```

No ejecute comandos `ip link set`: el servicio presupone que Linux ya creó y
configuró `can0`.

Configure `.env` con `J1939_ENABLED=true`, `J1939_TRANSPORT=socketcan` y
`J1939_CAN_INTERFACE=can0`. Para una prueba directa:

```bash
set -a
source .env
set +a
python services/j1939_can_service.py
```

En otra terminal, las dos lecturas pueden coexistir pasivamente:

```bash
candump -L can0
curl http://127.0.0.1:8765/api/j1939/status
curl http://127.0.0.1:8765/api/j1939/signals
curl http://127.0.0.1:8080/api/j1939/status
curl http://127.0.0.1:8080/api/j1939/signals
```

## systemd y Flask

Instale la unidad solo después de revisar sus rutas:

```bash
sudo cp deploy/samee100-j1939.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now samee100-j1939.service
systemctl status samee100-j1939.service
journalctl -u samee100-j1939.service -f
```

Para aplicar un cambio de `J1939_ENABLED` en Flask, primero identifique la
unidad real y compruebe si los dos PID observados son padre e hijo del reloader:

```bash
systemctl --type=service | grep -i samee
ps -ef --forest | grep '[p]ython3\? -m api.app'
```

Luego reinicie la unidad Flask identificada mediante `systemctl restart
NOMBRE.service`. No use `kill -9`; en desarrollo interactivo detenga una sola
vez el proceso padre con `Ctrl+C` y vuelva a ejecutar `python3 -m api.app`.

## Rollback

```bash
sudo systemctl disable --now samee100-j1939.service
```

Deje `J1939_ENABLED=false`, reinicie Flask mediante su unidad real y restaure
los archivos desde la rama/commit anterior. No es necesario modificar `can0`,
SPI, Device Tree, SQLite, Modbus ni MQTT.
